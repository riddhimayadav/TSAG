# Project Content Checklist

Use this when gathering info from project leads to write or update a project page (`pages/projects/projectN.html`) or its summary card on the portfolio (`newsletter.html`). The goal is to replace generic, AI-sounding copy with grounded, specific content.

| # | What's needed | Best format | Feeds into |
|---|---|---|---|
| 1 | **Status** | Short phrase (e.g., "In progress — data collection phase") | Hero subtitle + "Where We Are Now" |
| 2 | **Client/partner** | Short phrase (name + 1-line context, or "confidential") | Hero / Challenge intro |
| 3 | **The actual ask** | 2-3 sentence paragraph, in the client's own words if possible | "The Challenge" section |
| 4 | **Team** | List (names + roles) | Optional credit line, skip if privacy concern |
| 5 | **Timeframe** | Short phrase (e.g., "Started Fall 2026, ongoing") | "Where We Are Now" |
| 6 | **Data sources & tools** | List (tool/platform name → one-line purpose each) | "Research Methods & Tools" grid |
| 7 | **Actual methodology** | 1-2 short paragraphs, plain-language explanation of the technique used | "Our Approach" |
| 8 | **Concrete findings so far** | Bullet list if 2+ findings exist, otherwise a short paragraph; write "none yet" explicitly if there are none | New "Findings So Far" section (only if non-empty) |
| 9 | **Actual deliverables** | List (deliverable name → status: done/in progress/planned → 1-line description) | "What We're Delivering" grid |
| 10 | **Visuals** | Image files (screenshots, charts, logos), not text | Replaces generic gradient placeholder cards |
| 11 | **What's next** | 2-3 sentence paragraph, concrete next steps only | "Where We Are Now" closer |

## Notes
- Don't write content that implies a project is complete when it isn't — say where it actually stands.
- Prefer real numbers, named tools, and named data sources over vague phrasing ("data-driven framework", "holistic view", etc.).
- If a client or data source must stay confidential, note that explicitly instead of vaguely gesturing around it.
